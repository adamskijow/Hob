# v0.9.10 evening-recap semantic safety audit

Date: 2026-07-24. Parent: v0.9.9.

## Customer outcome

An answer to Hob's active evening recap is now independently understood before
any task change is allowed. The owner can report zero progress naturally,
including terse slang, idiom, humor, another language, or profanity. There is
no magic phrase and no application-side phrase list.

Explicit task commands, new tasks, positive completion reports, partial
progress, questions, and social replies remain available while the recap is
active. If the independent check is unavailable, malformed, contradictory,
or uncertain, Hob changes nothing and asks the owner to retry.

## Daily-use incident and root cause

The live EOD prompt listed two open tasks. The owner replied “Jack shit bud,”
meaning zero completed work. The main model proposed dropping the second task,
and Hob applied it.

The focused recap pass existed, but deterministic code called it only when the
first pass returned exactly one `recap`, `chitchat`, or `unknown` action. A
mistaken mutation therefore excluded itself from review. The guard trusted the
classification it was meant to verify.

The first attempted repair widened the old three-value enum check. Real-model
testing exposed structured-output order bias: the 14B model returned the first
enum value for explicit “drop the second one” and “new task: buy milk.” That
safe but unusable behavior was not released.

The final contract asks the model to paraphrase the utterance first, then emit
three independent booleans: zero-completion report, pure social reply, and
explicit task request. Positive work/progress has all three false. The core
accepts only one high-confidence semantic state and otherwise fails closed.

  paused through its authenticated control API for the gate and restored
  afterward; status must return healthy. The observed direct-port/deep-probe
  false restart is retained as 1.0 operational evidence, not counted as a model
  failure.
- Live database backup, exact before-state restoration of batch `b52`, daemon
  restart on the release commit, clean queues, schema 10, and a Telegram replay.

## 1.0 implication

This closes a P0 semantic-mutation hole, but it also reinforces the broader 1.0
rule: a focused audit must be selected by machine-owned conversational context,
not by whether the first model output happens to look suspicious. The remaining
1.0 priorities are poison-queue recovery, time-correct durable onboarding,
DST policy/evidence, supported-model proof, accessibility, and sustained daily
use.

## Decision

Release as v0.9.10 only after all gates pass on the exact release commit, the
live task is restored from its recorded before-state, the daemon runs the
release commit, and a phone replay confirms both a natural zero-work reply and
an explicit task command behave correctly.
