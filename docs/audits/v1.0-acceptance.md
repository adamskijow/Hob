## Highest-risk findings

### Timezone setup

`HOB_TIMEZONE` defaults to UTC. Chat setup asks about hours and days without
confirming timezone. First-run must derive or confirm a visible timezone before
scheduling messages.

### Poison queues

Inbox and outbox processing stops at the first failure. This preserves order for
transient faults, but a permanent row can block every later turn. 1.0 needs
local, privacy-safe inspect, retry, quarantine, and recovery commands while
preserving at-most-once mutation.

### DST policy

Planning uses timezone-aware wall times. Spring-forward gaps and fall-back
duplicates need explicit behavior across reminders, fixed tasks, Calendar,
recurrence, sessions, digest, and recap.

### Supported model

Documentation defaults to `qwen2.5:7b-instruct`; release evaluation uses 14B.
The declared default must pass the corpus on target hardware, or the product
must require 14B and state resource expectations.

### Model supervision

Hearth deep probes can queue behind long 14B work and restart a healthy Ollama
process. The install needs an in-flight signal, serialized probes, or a timeout
validated against tail latency.

### Storage envelope

Completed delivery metadata and reply anchors expire after 30 days and cap at
1,000 rows per table. Logs cap at four 5 MiB generations. Action, digest, and
plan history remain unbounded. 1.0 needs a multi-year fixture, latency targets,
and a history-retention decision.

## Required release rehearsals

1. Fresh install through first digest and adopted plan.
2. Upgrade from released v0.8 and v0.9 data.
3. Verified backup, restore, rollback, and interaction.
4. Logout/login, reboot, sleep/wake, and service recovery.
5. Calendar grant, denial, revocation, timeout, and DST edges.
6. Model and Telegram transient/permanent failures.
7. Database busy, disk-full, corruption, and poison-queue recovery.
8. Unauthorized Telegram user, group, callback, reaction, and message-ID
   collision probes.
9. VoiceOver, keyboard-only, text-only, contrast, and dynamic-type pass.
10. Seven consecutive days of privacy-safe daily-use evidence.

## Scope limits

- Calendar writes and automatic task moves
- Third-party cloud storage and multi-user mode
- Behavior-derived scoring, estimate learning, and hidden memory
- Voice transcription without a local bounded design
- Proactive messages beyond digest, recap, reminders, session nudges, and one
  release note

## Final gate

- Every open P0/P1 has a regression and manual or live evidence.
- Python, native, real-model, EventKit, and exact-commit CI gates pass.
- Rehearsals above pass on the release candidate.
- Version, package metadata, docs, schema, backup, tag, release, installed app,
  and status agree on 1.0.0.
- Product claims match tested behavior.
