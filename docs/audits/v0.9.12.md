# v0.9.12 teapot identity and context-isolation audit

## Trigger

Hearth already uses a flame in the macOS menu bar. Giving Hob the same symbol
made two companion products harder to distinguish and contradicted Hob's
existing kettle avatar.

Daily use also exposed a context-isolation failure after the evening recap.
The first model pass correctly interpreted `Emissions tomorrow` as a dated
capture, but the recap safety pass treated “this does not answer the recap” as
“zero displayed tasks were completed” and swallowed the capture.

A second daily-use case exposed the same class of failure in the morning stale
prompt. For `I finished emissions!!`, the main model pass correctly proposed
completing emissions, but the focused context pass replaced it with dropping
the separately prompted business-case item.

A third case appeared after the next morning digest. `Haircut got scheduled for
next Friday` was durably received and correctly proposed as a reschedule, but
last night's still-live EOD list and the newer morning stale prompt both audited
the turn. Their contradictory verdict was mislabeled as “model unavailable,” so
the inbox retried forever while Telegram repeatedly showed typing.

Recovering that message exposed a separate calendar defect. The model retained
the typed distinction between `this Friday` and `next Friday`, but deterministic
weekday resolution ignored `which` and mapped both phrases to the upcoming
Friday.

Daily use then exercised the far-future safeguard with `buy bananas in 10
years`. Hob correctly held the task, but the message only repeated the date and
asked for confirmation. It did not say that the five-year threshold had
triggered a typo check, so a new safety prompt appeared arbitrary.

## Usability and customer experience

- Hob now uses a custom monochrome teapot mark derived from its existing avatar
  rather than borrowing Hearth's identity.
- Running is a filled teapot; off is an outlined teapot. Checking, paused, and
  unavailable states add compact badges without replacing the product mark.
- The open menu retains explicit state text, so color and icon recognition are
  never the only status signal.
- The compact menu-bar mark and the larger menu header use the same geometry.
- Proactive prompts are non-modal: completing another task, capturing new work,
  asking a question, or changing a preference keeps its own meaning instead of
  being forced into the last stale-task question.

## Onboarding

- Setup, deployment, feature, README, acceptance, and one-time digest language
  consistently tell the owner to look for the teapot.
- The one-time note explicitly says Hearth keeps the flame, resolving the most
  likely source of confusion for an owner who runs both products.
- Setup questions use the same context-isolation contract. An explicit setting
  is applied as the setting rather than being swallowed by an erroneous
  skip/cancel interpretation.

## Bugs and feature robustness

- The teapot is drawn with SwiftUI paths rather than relying on a newer SF
  Symbol that may be absent on Hob's macOS 13 deployment target.
- Status badge mappings are unit-tested, including the absence of a badge while
  running and distinct paused, checking, and warning states.
- The icon is vector and template-colored, so it follows macOS menu-bar
  contrast instead of embedding a light- or dark-mode bitmap.
- Recap adjudication now asks the model for two separate semantic axes: whether
  the message answers the recap and what the message itself is trying to do.
  New tasks, questions, and social turns no longer become implicit zero reports
  merely because they omit the displayed work.
- Zero-completion language remains model-owned rather than a code phrase list.
  The core only validates the typed relationship: a zero report needs explicit
  textual evidence and cannot simultaneously be a new task or request.
- The exact screenshot case has interpreter and end-to-end mutation tests.
  Contradictory verdicts fail closed. Real `qwen2.5:14b-instruct` replay
  preserved `Emissions tomorrow` and `Dentist Friday` as dated captures while
  understanding `nada` and `Jack shit bud` as zero-completion reports.
- Morning nudge, risky-confirmation, and onboarding adjudication now classify
  both whether the active question was answered and the message's primary
  intent, with literal answer evidence. The independent pass sees the first
  typed proposal instead of judging the utterance in isolation.
- A contextual decision cannot replace a different concrete task, work-update,
  setting, or request action. Destructive nudge actions remain confined to the
  machine-owned target, while natural `keep`, explicit `drop`, confirmation,
  and setup controls retain their ordinary paths.
- A successfully delivered morning digest now becomes the newest presented
  list and supersedes last night's EOD context in the same transaction as its
  digest and nudge records. Newer nudge, confirmation, onboarding, forwarded,
  and pending contexts also suppress EOD adjudication defensively.
- Only an exception from an actual model call is marked retryable. Low
  confidence, malformed semantic relationships, and disagreement between model
  passes now produce one bounded clarification instead of impersonating an
  outage and poisoning the head of the durable inbox.
- Named weekdays now retain their calendar meaning end to end. Bare or `this`
  resolves to the upcoming occurrence, while `next` resolves inside the next
  Monday-to-Sunday week. On Tuesday 2026-08-11, that makes `this Friday`
  2026-08-14 and `next Friday` 2026-08-21.
- Far-future capture, reschedule, and deadline confirmations now name the
  affected work, state the exact date and rough distance, then ask `are you
  sure?` Telegram's button says `Confirm`, not the ambiguous `Yes`.
- Release-gate variation exposed two correct task outcomes with incorrect
  conversational lifecycle state. An exact model-proposed resume of the active
  waiting item now consumes that machine-owned nudge after reference
  reconciliation, including `id: label` targets. Onboarding's independent pass
  uses distinct `keep current and continue now` and `pause setup` outcomes, so
  `finish setup later` cannot become a step skip.
- The full release gate then exposed an identity error: `the prez deck is
  waiting on Sam's slides` could become a second captured task instead of
  parking the existing deck. Capture review now has a typed `wait` outcome and
  a separate semantic identity pass. It accepts an existing-task edit only when
  the message's subject denotes that same work; distinct new blocked work stays
  a waiting capture. This remains model-owned and does not use a phrase list.
- Real `qwen2.5:14b-instruct` replay now returns `Complete a33` for the exact
  emissions sentence and explicitly classifies it as a work update that leaves
  the stale question unanswered. Natural keep and explicit drop replays pass.
- The live erroneous drop was reversed from action-log batch `b55`, emissions
  was completed under the original inbound message, the later haircut capture
  was preserved, and the unanswered nudge context was restored. The pre-repair
  SQLite backup passed integrity validation.
- The exact haircut message was retained through 12 failed attempts without a
  mutation. After deployment, the original inbox row—not a replacement—moved
  Willow's haircut once, delivered one reply, cleared its prior error, and left
  inbound/outbound/failed queue counts at zero. The incorrect 2026-08-14 date
  was then corrected through Hob's ordinary mutation and undo-log path to
  2026-08-21 after the weekday-resolution defect was found.
