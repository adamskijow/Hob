# v0.9.12 teapot identity audit

## Trigger

Hearth already uses a flame in the macOS menu bar. Giving Hob the same symbol
made two companion products harder to distinguish and contradicted Hob's
existing kettle avatar.

## Usability and customer experience

- Hob now uses a custom monochrome teapot mark derived from its existing avatar
  rather than borrowing Hearth's identity.
- Running is a filled teapot; off is an outlined teapot. Checking, paused, and
  unavailable states add compact badges without replacing the product mark.
- The open menu retains explicit state text, so color and icon recognition are
  never the only status signal.
- The compact menu-bar mark and the larger menu header use the same geometry.

## Onboarding

- Setup, deployment, feature, README, acceptance, and one-time digest language
  consistently tell the owner to look for the teapot.
- The one-time note explicitly says Hearth keeps the flame, resolving the most
  likely source of confusion for an owner who runs both products.

## Bugs and feature robustness

- The teapot is drawn with SwiftUI paths rather than relying on a newer SF
  Symbol that may be absent on Hob's macOS 13 deployment target.
- Status badge mappings are unit-tested, including the absence of a badge while
  running and distinct paused, checking, and warning states.
- The icon is vector and template-colored, so it follows macOS menu-bar
  contrast instead of embedding a light- or dark-mode bitmap.

## Release gates

- Debug and optimized Swift builds pass on the macOS 13 deployment target.
- All Open Local service/health/branding tests, Python tests, plist lint, and
  macOS/Ubuntu CI pass.
- Install into daily use and confirm the teapot is visible, its menu reports
  the live daemon PID, and restart retains clean operational health.
