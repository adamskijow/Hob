# v0.9.6 numbered-exclusion and singleton audit

## Incidents

- `Finished it all except 1 and 6` could use current list positions after earlier
  rows closed, shifting the intended exclusions.
- Separate local databases could poll the same Telegram bot.
- Two database locations could make recovery commands choose the wrong data.

## Fix

- Preserve displayed-list IDs and positions for bulk exclusions.
- Reject out-of-range exclusions.
- Add a private token-scoped local process lease.
- Refuse ambiguous legacy and app-data database selection.
- Keep CLI help independent of daemon configuration.

## Evidence

Production bulk wording, closed-row positions, named exclusions, duplicate bot
leases, distinct tokens, private lock paths, help, and database ambiguity all
received regressions.

## Current status

v0.9.8 moved free-text bulk meaning to typed model output. Displayed identity,
literal exclusions, process lease, and database selection remain code-owned.
